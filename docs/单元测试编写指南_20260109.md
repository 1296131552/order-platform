## 测试规范

### 命名规范

**测试类命名**：
```java
// 格式：{ClassName}Test
class OperationLogAspectTest { }
class AuthServiceImplTest { }
```

**测试方法命名**：
```java
// 格式：should{ExpectedResult}_{scenario}_{condition}()
void shouldPass_simpleVariableReference() { }
void shouldReject_classReference() { }
void shouldLogin_success_withUsername() { }
void shouldRejectLogin_wrongPassword() { }
```

**使用 @DisplayName 注解**：
```java
@Test
@DisplayName("✅ 应该通过简单的变量引用")
void shouldPass_simpleVariableReference() { }
```

### AAA 模式

```java
@Test
@DisplayName("✅ 应该成功登录（用户名）")
void shouldLogin_success_withUsername() {
    // ==================== Arrange（准备）====================
    // 准备测试数据和 mock 对象
    when(userMapper.selectByUsername("testuser")).thenReturn(testUser);
    when(passwordEncoderUtil.matches(anyString(), anyString())).thenReturn(true);

    // ==================== Act（执行）====================
    // 调用被测方法
    LoginVO result = authService.login(validLoginDTO);

    // ==================== Assert（断言）====================
    // 验证结果
    assertThat(result).isNotNull();
    assertThat(result.getToken()).isEqualTo(validToken);

    // 验证 mock 调用
    verify(userMapper).selectByUsername("testuser");
}
```

### Mock 使用规范

```java
// 1. 使用 @Mock 注解
@Mock
private UserMapper userMapper;

// 2. 使用 Mockito.mock()
UserMapper mockMapper = mock(UserMapper.class);

// 3. Mock 方法调用
when(userMapper.selectByUsername("testuser")).thenReturn(testUser);

// 4. Mock 抛出异常
when(userMapper.selectByUsername("nonexistent"))
    .thenThrow(new BusinessException("用户不存在"));

// 5. 验证调用次数
verify(userMapper, times(1)).selectByUsername("testuser");
verify(userMapper, never()).deleteById(any());

// 6. 参数匹配
verify(userMapper).selectByUsername(eq("testuser"));
verify(userMapper).selectById(anyLong());
verify(userMapper).selectByUsername(argThat(s -> s != null && s.length() > 0));
```

### 断言规范

```java
// 使用 AssertJ（推荐）
assertThat(result).isNotNull();
assertThat(result.getToken()).isEqualTo(validToken);
assertThat(userList).hasSize(5);
assertThat(username).startsWith("test");
assertThat(exception).isInstanceOf(BusinessException.class);

// 不推荐使用 JUnit 断言
assertEquals(expected, actual);
assertNull(result);
```

## 最佳实践

### 1. 测试隔离

```java
// ✅ 好的做法：每个测试独立
@Test
void test1() {
    // 独立的测试数据和 mock
}

@Test
void test2() {
    // 独立的测试数据和 mock
}

// ❌ 不好的做法：测试间有依赖
private static String sharedState;

@Test
void test1() {
    sharedState = "value";
}

@Test
void test2() {
    // 依赖 test1 的执行顺序
    assertThat(sharedState).isEqualTo("value");
}
```

### 2. 使用 @Nested 分组

```java
@Nested
@DisplayName("用户登录功能测试")
class LoginTests {
    @Test
    void shouldLogin_success() { }

    @Test
    void shouldRejectLogin_wrongPassword() { }
}

@Nested
@DisplayName("Token 刷新功能测试")
class RefreshTokenTests {
    @Test
    void shouldRefreshToken_success() { }
}
```

### 3. 测试数据构建器

```java
// 创建测试数据构建器
private User createTestUser() {
    User user = new User();
    user.setId(1L);
    user.setUsername("testuser");
    user.setEmail("test@example.com");
    return user;
}

// 使用 @BeforeEach 初始化
@BeforeEach
void setUp() {
    testUser = createTestUser();
    validLoginDTO = new LoginDTO();
    validLoginDTO.setAccount("testuser");
    validLoginDTO.setPassword("Test123456!");
}
```

### 4. 测试覆盖率目标

| 代码类型 | 覆盖率目标 | 说明 |
|---------|----------|------|
| **核心业务逻辑** | ≥ 80% | 认证、授权、支付等 |
| **工具类** | ≥ 90% | 字符串处理、加密等 |
| **配置类** | ≥ 60% | 配置加载、初始化 |
| **DTO/Entity** | ≥ 40% | 简单的 getter/setter |

### 5. 安全测试重点

```java
// ✅ 测试边界条件
@Test
void shouldReject_exceedsMaxLength() {
    String expression = "#a".repeat(201);
    assertThatThrownBy(() -> validate(expression))
        .isInstanceOf(SecurityException.class);
}

// ✅ 测试恶意输入
@Test
void shouldReject_commandInjection() {
    String[] attacks = {
        "#user'; rm -rf /; echo '",
        "#user.name && cat /etc/passwd"
    };
    for (String attack : attacks) {
        assertThatThrownBy(() -> validate(attack))
            .isInstanceOf(SecurityException.class);
    }
}

// ✅ 测试安全机制
@Test
void shouldPreventTimingAttack() {
    long duration1 = measureTime(() -> login("user", "pass1"));
    long duration2 = measureTime(() -> login("user", "pass2"));

    // 验证耗时相近（防止时序攻击）
    double ratio = (double) duration2 / duration1;
    assertThat(ratio).isLessThan(10.0);
}
```

## CI/CD 集成

### GitHub Actions 配置

在 `.github/workflows/test.yml` 中添加：

```yaml
name: 单元测试

on:
  push:
    branches: [ main, develop ]
  pull_request:
    branches: [ main, develop ]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - name: 检出代码
        uses: actions/checkout@v4

      - name: 设置 JDK
        uses: actions/setup-java@v4
        with:
          distribution: 'temurin'
          java-version: '21'
          cache: 'maven'

      - name: 运行测试
        run: mvn test

      - name: 生成覆盖率报告
        run: mvn test jacoco:report

      - name: 上传覆盖率报告
        uses: codecov/codecov-action@v3
        with:
          files: '**/target/site/jacoco/jacoco.xml'
```

### 测试覆盖率要求

```xml
<!-- pom.xml -->
<plugin>
    <groupId>org.jacoco</groupId>
    <artifactId>jacoco-maven-plugin</artifactId>
    <configuration>
        <rules>
            <rule>
                <element>PACKAGE</element>
                <limits>
                    <limit>
                        <counter>LINE</counter>
                        <value>COVEREDRATIO</value>
                        <minimum>0.60</minimum> <!-- 最低 60% 覆盖率 -->
                    </limit>
                </limits>
            </rule>
        </rules>
    </configuration>
</plugin>
```

## 常见问题

### Q1: Mock 对象方法未生效

**问题**：
```java
when(userMapper.selectById(1L)).thenReturn(user);
User result = userService.getUser(1L);
// result 为 null
```

**原因**：测试类缺少 `@ExtendWith(MockitoExtension.class)` 注解

**解决**：
```java
@ExtendWith(MockitoExtension.class)
class UserServiceTest {
    // ...
}
```

### Q2: ReflectionTestUtils 找不到方法

**问题**：
```java
ReflectionTestUtils.invokeMethod(aspect, "validateExpression", expr);
// 抛出异常
```

**原因**：方法是 private 的，且参数类型不匹配

**解决**：
```java
// 确保方法签名匹配
ReflectionTestUtils.invokeMethod(
    operationLogAspect,
    "validateExpression",
    expression  // 参数类型必须是 String
);
```

### Q3: 测试在 CI 环境失败

**常见原因**：
- 测试依赖本地环境（文件路径、时区）
- 测试耗时过长（超时）
- 测试间有依赖（执行顺序问题）

**解决**：
```java
// ✅ 使用相对路径
String path = "src/test/resources/test.txt";

// ✅ 设置超时
@Test
@Timeout(5)  // 5 秒超时
void longRunningTest() { }

// ✅ 确保测试独立
@BeforeEach
void setUp() {
    // 每个测试前重新初始化
}
```

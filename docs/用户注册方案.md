## 1. 核心设计

### 1.1 设计目标

| 需求 | 优先级 | 说明 |
|------|--------|------|
| **双渠道注册** | P0 | 自主注册 + 管理员创建 + 邀请码 |
| **统一注册表** | P0 | 所有用户创建都记录到注册申请表 |
| **完整溯源** | P0 | 任何用户的创建历史都可追溯 |
| **审核机制** | P0 | 自主注册需要审核通过后才能登录 |
| **灵活注册** | P0 | 邮箱和手机号二选一，降低注册门槛 |

### 1.2 核心架构

**统一注册表思想**：所有用户创建都经过 `t_user_registration` 表

```
v2.1 之前的问题：
  自主注册 → t_user_registration → t_user ✅ 有溯源
  管理员创建 → t_user ❌ 无溯源

v2.2 改进：
  自主注册   → t_user_registration (PENDING) → 审核 → t_user
  管理员创建 → t_user_registration (NONE) + t_user 同时创建
  邀请码注册 → t_user_registration (NONE) + t_user 同时创建
```

**三大注册渠道对比**：

| 维度 | 自主注册 | 管理员创建 | 邀请码注册 |
|------|---------|-----------|-----------|
| **注册表记录** | ✅ 创建（PENDING） | ✅ 创建（NONE） | ✅ 创建（NONE） |
| **用户表记录** | 审核后创建 | 同时创建 | 同时创建 |
| **creator_type** | USER | ADMIN | USER |
| **source** | SELF_REGISTER | ADMIN_CREATE | INVITE_CODE |
| **审核流程** | 需要 | 不需要 | 不需要 |
| **首次登录改密** | ❌ 不需要 | ✅ 强制改密 | ❌ 不需要 |
| **使用场景** | 外部合作伙伴 | 内部员工 | 特殊合作伙伴 |

### 1.3 关键特性

✅ **统一数据源**：所有用户创建都记录到注册申请表
✅ **完整审计链**：追溯任何用户的创建历史（创建人、来源）
✅ **数据一致性**：统一的数据结构和创建流程
✅ **灵活注册**：邮箱和手机号二选一，降低注册门槛
✅ **多种登录方式**：支持用户名/邮箱/手机号三种方式登录

## 2. 注册流程

### 2.1 自主注册流程

```
1. 用户访问注册页面，填写信息（用户名、密码、邮箱/手机号二选一）
   ↓
2. 后端验证：用户名唯一性、联系方式唯一性、密码强度
   ↓
3. 创建注册申请记录（t_user_registration）：
   - audit_status = 'PENDING'
   - creator_type = 'USER'
   - source = 'SELF_REGISTER'
   - 密码BCrypt加密存储
   ↓
4. 返回："注册成功，请等待管理员审核"
   ↓
5. 管理员审核
   ├─ 审核通过 → 创建 t_user 记录 → 关联 user_id → 发送通知
   └─ 审核拒绝 → 更新状态为 REJECTED → 填写备注 → 发送通知
   ↓
6. 用户登录（审核通过后）
```

### 2.2 管理员创建流程

```
1. 管理员填写用户信息（用户名、邮箱/手机号二选一、角色）
   ↓
2. 设置默认密码（如123456）
   ↓
3. 后端验证：用户名唯一性、联系方式唯一性
   ↓
4. 开启事务，同时创建两条记录：
   ├─ t_user_registration（audit_status='NONE', creator_type='ADMIN'）
   └─ t_user（audit_status='NONE', is_first_login=1）
   ↓
5. 关联 user_id
   ↓
6. 用户首次登录 → 强制改密
```

### 2.3 邀请码注册流程（未来实现）

```
1. 管理员生成邀请码（设置过期时间、使用次数、预设角色）
   ↓
2. 合作伙伴输入邀请码 + 填写基本信息
   ↓
3. 后端验证邀请码有效性
   ↓
4. 同时创建两条记录：
   ├─ t_user_registration（source='INVITE_CODE'）
   └─ t_user（自动分配预设角色）
   ↓
5. 用户可直接登录
```

## 3. 数据库设计

### 3.1 注册申请表（t_user_registration）

**表结构**：

```sql
CREATE TABLE t_user_registration (
    -- 主键
    id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '主键ID',

    -- 基本信息（email和phone二选一必填）
    username VARCHAR(50) NOT NULL COMMENT '用户名',
    password VARCHAR(255) NOT NULL COMMENT '密码（BCrypt加密）',
    real_name VARCHAR(50) COMMENT '真实姓名',
    email VARCHAR(100) COMMENT '邮箱（与phone二选一必填）',
    phone VARCHAR(20) COMMENT '手机号（与email二选一必填）',
    employee_no VARCHAR(50) COMMENT '工号',
    position VARCHAR(50) COMMENT '职位',

    -- 申请信息
    apply_role VARCHAR(50) COMMENT '申请角色',
    apply_reason VARCHAR(500) COMMENT '申请原因',

    -- 创建人信息
    creator_id BIGINT COMMENT '创建人ID',
    creator_type VARCHAR(20) NOT NULL DEFAULT 'USER' COMMENT '创建人类型: USER/ADMIN/SYSTEM',
    source VARCHAR(50) COMMENT '来源: SELF_REGISTER/ADMIN_CREATE/INVITE_CODE/BATCH_IMPORT',

    -- 邀请码信息
    invite_code VARCHAR(50) COMMENT '使用的邀请码',

    -- 审核字段
    audit_status VARCHAR(20) NOT NULL DEFAULT 'PENDING' COMMENT 'PENDING/APPROVED/REJECTED/NONE',
    audit_remark VARCHAR(500) COMMENT '审核备注',
    audit_by BIGINT COMMENT '审核人ID',
    audit_time DATETIME COMMENT '审核时间',

    -- 关联字段
    user_id BIGINT COMMENT '关联的用户ID',

    -- 基础字段
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    is_deleted TINYINT NOT NULL DEFAULT 0,

    -- 唯一索引（支持逻辑删除）
    UNIQUE KEY uk_username (username, is_deleted),
    UNIQUE KEY uk_email (email, is_deleted),
    UNIQUE KEY uk_phone (phone, is_deleted),

    -- 查询优化索引
    INDEX idx_audit_status_created (audit_status, created_at),
    INDEX idx_user_id (user_id),
    INDEX idx_creator (creator_id, creator_type)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

**字段说明**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| username | VARCHAR(50) | ✅ | 用户名，唯一索引 |
| password | VARCHAR(255) | ✅ | 密码（BCrypt加密） |
| email | VARCHAR(100) | ⚠️ | 邮箱，与phone二选一 |
| phone | VARCHAR(20) | ⚠️ | 手机号，与email二选一 |
| real_name | VARCHAR(50) | ❌ | 真实姓名 |
| employee_no | VARCHAR(50) | ❌ | 工号（内部员工） |
| position | VARCHAR(50) | ❌ | 职位 |
| apply_role | VARCHAR(50) | ❌ | 申请角色 |
| creator_id | BIGINT | ❌ | 创建人ID |
| creator_type | VARCHAR(20) | ✅ | 创建人类型，默认USER |
| source | VARCHAR(50) | ❌ | 来源渠道 |
| audit_status | VARCHAR(20) | ✅ | 审核状态，默认PENDING |
| invite_code | VARCHAR(50) | ❌ | 邀请码（邀请码注册） |
| user_id | BIGINT | ❌ | 关联用户ID |

> **⚠️ 重要说明**：
> - `email` 和 `phone` 在数据库层面可空，但**应用层要求至少填写一个**
> - 支持不同场景：国外用户（只有邮箱）、个体司机（只有手机号）、内部员工（两者都有）

## 4. 业务逻辑设计

### 4.1 应用层校验规则

**核心校验逻辑**：

```java
/**
 * 注册信息校验
 */
public void validateRegistrationInfo(RegisterDTO dto) {
    // 1. 用户名必填
    if (StringUtils.isBlank(dto.getUsername())) {
        throw new BusinessException("用户名不能为空");
    }

    // 2. 密码必填
    if (StringUtils.isBlank(dto.getPassword())) {
        throw new BusinessException("密码不能为空");
    }

    // 3. 邮箱和手机号二选一必填
    if (StringUtils.isBlank(dto.getEmail()) && StringUtils.isBlank(dto.getPhone())) {
        throw new BusinessException("邮箱和手机号至少填写一个");
    }

    // 4. 邮箱格式校验（如果填写了）
    if (StringUtils.isNotBlank(dto.getEmail()) && !isValidEmail(dto.getEmail())) {
        throw new BusinessException("邮箱格式不正确");
    }

    // 5. 手机号格式校验（如果填写了）
    if (StringUtils.isNotBlank(dto.getPhone()) && !isValidPhone(dto.getPhone())) {
        throw new BusinessException("手机号格式不正确");
    }

    // 6. 密码强度校验（6-20位，至少满足3项）
    if (!isStrongPassword(dto.getPassword())) {
        throw new BusinessException("密码强度不足");
    }
}

/**
 * 唯一性校验（两表联合查询）
 */
public void checkUniqueness(RegisterDTO dto) {
    // 用户名唯一性
    if (checkUsernameExists(dto.getUsername())) {
        throw new BusinessException("用户名已存在");
    }

    // 邮箱唯一性（如果填写了）
    if (StringUtils.isNotBlank(dto.getEmail()) && checkEmailExists(dto.getEmail())) {
        throw new BusinessException("邮箱已被使用");
    }

    // 手机号唯一性（如果填写了）
    if (StringUtils.isNotBlank(dto.getPhone()) && checkPhoneExists(dto.getPhone())) {
        throw new BusinessException("手机号已被使用");
    }
}
```

### 4.2 登录逻辑

**支持三种登录方式**：用户名、邮箱、手机号

```java
/**
 * 统一登录接口
 */
@PostMapping("/login")
public Result<LoginVO> login(@RequestBody LoginDTO dto) {
    // 1. 判断登录方式并查询用户
    User user = null;
    if (isUsername(dto.getAccount())) {
        user = userService.getByUsername(dto.getAccount());
    } else if (isEmail(dto.getAccount())) {
        user = userService.getByEmail(dto.getAccount());
    } else if (isPhone(dto.getAccount())) {
        user = userService.getByPhone(dto.getAccount());
    } else {
        throw new BusinessException("账号格式不正确");
    }

    // 2. 用户不存在
    if (user == null) {
        throw new BusinessException("账号不存在");
    }

    // 3. 检查审核状态
    if ("PENDING".equals(user.getAuditStatus())) {
        throw new BusinessException("账号正在审核中");
    }
    if ("REJECTED".equals(user.getAuditStatus())) {
        throw new BusinessException("账号审核未通过");
    }

    // 4. 验证密码
    if (!passwordEncoderUtil.matches(dto.getPassword(), user.getPassword())) {
        throw new BusinessException("密码错误");
    }

    // 5. 生成Token
    String token = JwtUtil.generateToken(user.getId(), 7 * 24 * 60 * 60);

    // 6. 检查是否首次登录（管理员创建的用户）
    boolean isFirstLogin = (user.getIsFirstLogin() == 1);
    return Result.success(new LoginVO(token, user, isFirstLogin));
}
```

### 4.3 审核通过流程

```java
/**
 * 审核通过注册申请
 */
@Transactional(rollbackFor = Exception.class)
public void approveRegistration(Long registrationId, Long auditorId) {
    // 1. 查询注册申请
    UserRegistration registration = registrationMapper.selectById(registrationId);

    // 2. 创建正式用户
    User user = new User();
    BeanUtils.copyProperties(registration, user);
    user.setAuditStatus("APPROVED");
    user.setAuditBy(auditorId);
    user.setAuditTime(LocalDateTime.now());
    user.setIsFirstLogin(0); // 自主注册用户已设密码，无需改密
    userMapper.insert(user);

    // 3. 分配角色
    if (registration.getApplyRole() != null) {
        UserRole userRole = new UserRole();
        userRole.setUserId(user.getId());
        userRole.setRoleCode(registration.getApplyRole());
        userRoleMapper.insert(userRole);
    }

    // 4. 更新注册申请
    registration.setUserId(user.getId());
    registration.setAuditStatus("APPROVED");
    registration.setAuditBy(auditorId);
    registration.setAuditTime(LocalDateTime.now());
    registrationMapper.updateById(registration);

    // 5. 记录操作日志（异步）
    operationLogService.logApproval(registration, user);
}
```

### 4.4 管理员创建用户

```java
/**
 * 管理员创建用户
 */
@Transactional(rollbackFor = Exception.class)
public User createUserByAdmin(CreateUserDTO dto, Long adminId) {
    // 1. 检查唯一性（两表联合查询）
    if (checkUsernameExists(dto.getUsername())) {
        throw new BusinessException("用户名已存在");
    }

    // 2. 生成默认密码（BCrypt加密）
    String encodedPassword = passwordEncoderUtil.encode("123456");

    // 3. 创建注册申请记录（统一溯源）
    UserRegistration registration = new UserRegistration();
    registration.setUsername(dto.getUsername());
    registration.setPassword(encodedPassword);
    registration.setEmail(dto.getEmail());
    registration.setPhone(dto.getPhone());
    registration.setRealName(dto.getRealName());
    registration.setAuditStatus("NONE");
    registration.setCreatorId(adminId);
    registration.setCreatorType("ADMIN");
    registration.setSource("ADMIN_CREATE");
    registration.setApplyRole(dto.getRoles() != null ? dto.getRoles().get(0) : null);
    registrationMapper.insert(registration);

    // 4. 创建正式用户
    User user = new User();
    BeanUtils.copyProperties(dto, user);
    user.setPassword(encodedPassword);
    user.setAuditStatus("NONE");
    user.setIsFirstLogin(1); // 需要强制改密
    userMapper.insert(user);

    // 5. 分配角色
    if (dto.getRoles() != null) {
        for (String roleCode : dto.getRoles()) {
            UserRole userRole = new UserRole();
            userRole.setUserId(user.getId());
            userRole.setRoleCode(roleCode);
            userRoleMapper.insert(userRole);
        }
    }

    // 6. 关联 user_id
    registration.setUserId(user.getId());
    registrationMapper.updateById(registration);

    return user;
}
```

## 5. 安全机制

### 5.1 并发安全

**问题**：高并发下可能同时注册相同的用户名/邮箱/手机号

**解决方案**：数据库复合唯一索引

```sql
-- 支持逻辑删除的复合唯一索引
UNIQUE KEY uk_username (username, is_deleted)
UNIQUE KEY uk_email (email, is_deleted)
UNIQUE KEY uk_phone (phone, is_deleted)
```

**好处**：
- ✅ 数据库级别保证唯一性
- ✅ 应用层无需加锁
- ✅ 支持逻辑删除（`is_deleted=1`）
- ✅ MySQL 允许多个 NULL 值，不影响二选一场景

### 5.2 密码安全

| 措施 | 说明 |
|------|------|
| **BCrypt加密** | strength=10，自动加盐 |
| **密码强度验证** | 6-20位，至少满足3项（大小写字母、数字、特殊字符） |
| **首次登录改密** | 管理员创建用户强制改密 |
| **密码存储** | 注册申请表存储加密密码，审核通过后直接复制 |

### 5.3 审核状态控制


## 7. 设计决策

### 7.1 为什么使用独立的注册申请表？

**决策**：引入 `t_user_registration` 独立表存储注册申请

**原因**：
- ✅ 不占用用户表资源：PENDING状态的记录不影响正式用户表
- ✅ 审核拒绝后可重试：用户可以重新注册
- ✅ 数据隔离清晰：注册申请和正式用户完全分离
- ✅ 可追溯历史：保留完整的注册申请历史

**备选方案**：直接在 t_user 表存储，audit_status='PENDING'

**拒绝原因**：
- ❌ 占用用户名/邮箱/手机号资源
- ❌ 审核拒绝后无法重新注册
- ❌ 正式用户和注册申请混在一起

### 7.2 为什么管理员创建也要记录到注册表？

**决策**：管理员创建用户时，同时创建 t_user_registration 和 t_user 记录

**原因**：
- ✅ 统一数据源：所有用户创建都来自注册申请表
- ✅ 完整审计链：可以追溯任何用户的创建历史
- ✅ 数据一致性：统一的数据结构和创建流程
- ✅ 扩展性强：支持创建人绩效分析、用户来源统计

**拒绝备选方案**：管理员创建直接存 t_user，不经过注册表

### 7.3 为什么邮箱和手机号二选一必填？

**决策**：email 和 phone 在数据库层面可空，应用层要求至少填写一个

**原因**：
- ✅ 降低注册门槛：支持只有邮箱或只有手机号的用户
- ✅ 适应不同场景：国外用户（邮箱）、个体司机（手机号）、内部员工（两者都有）
- ✅ 提升用户体验：不强制要求两种联系方式

**拒绝备选方案**：都必填或都选填

### 7.4 为什么使用复合唯一索引（username, is_deleted）？

**决策**：复合唯一索引支持逻辑删除

**原因**：
- ✅ 支持逻辑删除：`is_deleted=1`的用户可以重名
- ✅ 数据库级别保证并发安全
- ✅ 应用层无需额外加锁

**拒绝备选方案**：单列唯一索引 `UNIQUE (username)`

### 7.5 为什么注册申请表要存储密码？

**决策**：`t_user_registration` 表存储 BCrypt 加密后的密码

**原因**：
- ✅ 审核通过后直接复制到 `t_user`，无需用户重新输入
- ✅ 用户体验好，一次输入密码即可
- ✅ 密码已加密，安全可控

**拒绝备选方案**：不存储密码，审核通过后让用户重新设置

## 8. 常见问题

### Q1：自主注册用户可以立即登录吗？

**A**：不可以。自主注册用户的信息存储在 `t_user_registration` 表中，`audit_status='PENDING'`，需要等待管理员审核通过后才能登录。

### Q2：邮箱和手机号可以只填一个吗？

**A**：可以。应用层要求至少填写一个，支持只有邮箱或只有手机号的场景。这是 v2.2 版本新增的灵活性设计。

### Q3：审核拒绝后，用户可以重新注册吗？

**A**：可以。审核拒绝后，`t_user_registration` 记录标记为 `REJECTED`，用户名/邮箱/手机号资源被释放，用户可以重新注册。

### Q4：并发注册相同的用户名会怎样？

**A**：数据库唯一索引会保证只有一个请求成功，其他请求会返回友好错误提示："用户名已存在"。

### Q5：如何追溯管理员创建的用户历史？

**A**：所有用户创建都记录在 `t_user_registration` 表中，包括管理员创建的用户。可以通过 `creator_id` 和 `creator_type='ADMIN'` 查询某个管理员创建的所有用户，也可以通过 `user_id` 查询某个用户的完整创建历史。

### Q6：支持哪些登录方式？

**A**：支持三种登录方式：
- 用户名登录：`admin`
- 邮箱登录：`admin@example.com`
- 手机号登录：`13800138000`

系统会根据输入的账号格式自动判断登录方式。

### Q7：审核通过后，注册申请记录会删除吗？

**A**：不会删除。注册申请记录会永久保留，只是更新 `audit_status='APPROVED'` 并关联 `user_id`，用于追溯注册历史。

### Q8：管理员创建用户为什么需要强制改密？

**A**：因为管理员通常使用默认密码（如123456）创建用户，强制改密可以确保账户安全。

## ⚡ 快速开始

### 1. 提交配置（一次性操作）

```bash
git add .github/ .semgrep/
git commit -m "[ci] 添加安全扫描 CI/CD 配置"  
git push origin develop
```

### 2. 验证安装

访问：`https://github.com/<owner>/<repo>/actions`

### 3. 手动测试

点击 **Run workflow** → **Run workflow** 按钮

## 🔧 三大扫描工具

### Semgrep（代码扫描）
- ⏱️ **耗时**：2-3 分钟
- 🎯 **用途**：常见安全问题
- 📋 **规则**：Java 社区规则 + 7 条自定义规则

### Dependency-Check（依赖扫描）
- ⏱️ **耗时**：5-10 分钟
- 🎯 **用途**：第三方库漏洞
- 📦 **数据库**：NVD（国家漏洞数据库）

### CodeQL（深度分析）
- ⏱️ **耗时**：15-30 分钟
- 🎯 **用途**：复杂逻辑漏洞
- 🔍 **技术**：数据流分析

## 🛠️ 本地运行

### Semgrep

```bash
# 扫描整个项目
semgrep --config .semgrep/semgrep.yaml .

# 仅扫描 Common 模块
semgrep --config auto order-platform-common/src

# 使用自定义规则
semgrep --config .semgrep/rules/custom-java-security.yml .
```

### 依赖检查

```bash
# 使用 Docker 运行
docker run --rm -v $(pwd):/app \
    owasp/dependency-check:latest \
    --scan /app --out /app/reports
```

## 🚨 处理安全问题

### 优先级

| 优先级 | 严重程度 | 处理时间 | 示例 |
|-------|---------|---------|------|
| **P0** | ERROR | 立即修复 | SQL 注入、硬编码密钥 |
| **P1** | WARNING | 3 天内 | JWT 无过期、日志敏感信息 |
| **P2** | INFO | 1 周内 | 代码风格、最佳实践 |

### 修复流程

1. **理解问题**：阅读错误信息和 CWE 说明
2. **查找方案**：搜索 OWASP 或 Stack Overflow
3. **实施修复**：编写安全代码
4. **本地验证**：运行 `semgrep` 确认问题解决
5. **提交 PR**：添加修复和测试

## 🎓 自定义规则

### 添加新规则

1. 编辑 `.semgrep/rules/custom-java-security.yml`

```yaml
rules:
  - id: custom.java.my-new-rule
    message: 检测到不安全的代码模式
    languages: [java]
    severity: WARNING
    pattern: |
      unsafe_pattern(...)
    metadata:
      category: security
```

2. 提交配置：

```bash
git add .semgrep/rules/custom-java-security.yml
git commit -m "[security] 添加自定义安全规则"
git push
```

3. 验证规则：

```bash
semgrep --config .semgrep/rules/custom-java-security.yml .
```

### 常见问题

**Q: 扫描超时怎么办？**
A: 增加 `timeout` 参数或仅扫描修改的文件 (`diff: aware`)

**Q: 如何忽略误报？**
A: 在代码中添加 `// nosemgrep` 注释或在配置中排除规则

**Q: 如何添加新的扫描规则？**
A: 编辑 `.semgrep/rules/custom-java-security.yml`

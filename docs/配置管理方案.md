## 概述

### 设计目标

1. **集中管理**：所有配置集中在 common 模块，避免分散
2. **类型安全**：使用 @ConfigurationProperties，提供类型检查和IDE提示
3. **易于维护**：修改配置无需改代码，支持热更新
4. **环境友好**：支持多环境配置（dev/test/prod）
5. **安全性**：敏感配置通过环境变量注入

### 设计原则

| 原则 | 说明 |
|------|------|
| **集中配置** | 配置类在 common 模块，统一管理 |
| **分散定义** | 配置文件在启动模块（user/api） |
| **类型安全** | @ConfigurationProperties + JSR-303 校验 |
| **环境变量** | 敏感配置优先使用环境变量 |
| **可测试** | 支持测试环境配置覆盖 |

## 配置类说明

### OrderPlatformProperties

**位置**：`common/config/OrderPlatformProperties.java`

**功能**：
- 集中管理所有业务配置
- 提供类型安全的配置访问
- 支持 JSR-303 校验

**配置结构**：

```java
@Component
@ConfigurationProperties(prefix = "order.platform")
public class OrderPlatformProperties {

    private Security security = new Security();  // 安全配置
    private Jwt jwt = new Jwt();                  // JWT配置
    private Cache cache = new Cache();            // 缓存配置

    // 安全配置
    public static class Security {
        private Password password = new Password();
        private Token token = new Token();
    }

    // JWT配置
    public static class Jwt {
        private String secret;
        private Long expiration;
        private Long refreshExpiration;
    }

    // 缓存配置
    public static class Cache {
        private int permissionTtl;
        private int roleTtl;
        private Boolean enabled;
    }
}
```

**配置项清单**：

| 配置项 | 路径 | 类型 | 默认值 | 说明 |
|--------|------|------|--------|------|
| **密码策略** |
| max-attempts | security.password.max-attempts | int | 5 | 密码错误最大尝试次数 |
| lock-minutes | security.password.lock-minutes | int | 30 | 账户锁定时长（分钟） |
| expire-days | security.password.expire-days | int | 90 | 密码过期天数 |
| min-length | security.password.min-length | int | 6 | 密码最小长度 |
| max-length | security.password.max-length | int | 20 | 密码最大长度 |
| min-strength | security.password.min-strength | int | 3 | 密码最小强度得分 |
| **Token策略** |
| expiration | security.token.expiration | long | 604800 | Token过期时间（秒） |
| **JWT** |
| secret | jwt.secret | string | - | JWT密钥（必须设置） |
| expiration | jwt.expiration | long | 604800 | Token过期时间（秒） |
| refresh-expiration | jwt.refresh-expiration | long | 1209600 | 刷新Token过期时间（秒） |
| **缓存** |
| permission-ttl | cache.permission-ttl | int | 300 | 权限缓存TTL（秒） |
| role-ttl | cache.role-ttl | int | 300 | 角色缓存TTL（秒） |
| enabled | cache.enabled | boolean | true | 是否启用缓存 |

## 配置文件说明

### application.yml

**位置**：`user/src/main/resources/application.yml`

**结构**：

```yaml
# 订单可视化平台配置
order:
  platform:
    # 安全配置
    security:
      password:
        max-attempts: 5
        lock-minutes: 30
        expire-days: 90
        min-length: 6
        max-length: 20
        min-strength: 3
      token:
        expiration: 604800

    # JWT配置
    jwt:
      secret: ${JWT_SECRET:dev-secret-key}
      expiration: 604800
      refresh-expiration: 1209600

    # 缓存配置
    cache:
      permission-ttl: 300
      role-ttl: 300
      enabled: true

# JWT配置（兼容性）
jwt:
  secret: ${JWT_SECRET:dev-secret-key}
  expiration: 604800
```

### 环境变量支持

敏感配置支持通过环境变量覆盖：

| 环境变量 | 配置项 | 说明 |
|----------|--------|------|
| `JWT_SECRET` | jwt.secret | JWT密钥（生产环境必须设置） |

**使用示例**：

```bash
# Linux/Mac
export JWT_SECRET=your-256-bit-secret-key

# Windows
set JWT_SECRET=your-256-bit-secret-key

# Docker
docker run -e JWT_SECRET=your-256-bit-secret-key ...

# Kubernetes
env:
  - name: JWT_SECRET
    valueFrom:
      secretKeyRef:
        name: jwt-secret
        key: secret
```

## 使用示例

### 在 Service 中使用配置

**方式 1：注入 OrderPlatformProperties**

```java
@Service
@RequiredArgsConstructor
public class AuthServiceImpl implements AuthService {

    private final OrderPlatformProperties properties;

    public void someMethod() {
        // 读取配置
        int maxAttempts = properties.getSecurity().getPassword().getMaxAttempts();
        long expiration = properties.getJwt().getExpiration();

        // 使用配置
        log.info("最大尝试次数: {}", maxAttempts);
        log.info("Token过期时间: {}秒", expiration);
    }
}
```

**方式 2：使用 @Value 注解（不推荐）**

```java
@Service
public class SomeService {

    @Value("${order.platform.security.password.max-attempts}")
    private int maxAttempts;

    // 缺点：分散、不易管理、无类型安全
}
```

### 配置校验

OrderPlatformProperties 使用 JSR-303 校验：

```java
@Min(value = 1, message = "密码错误最大尝试次数不能小于1")
@Max(value = 10, message = "密码错误最大尝试次数不能大于10")
private int maxAttempts = 5;
```

**配置错误时的行为**：

```yaml
# 错误配置
order:
  platform:
    security:
      password:
        max-attempts: 15  # 超过最大值10
```

**启动时报错**：
```
***************************
APPLICATION FAILED TO START
***************************

Description:
Binding to target OrderPlatformProperties failed:

    Property: order.platform.security.password.max-attempts
    Value: 15
    Reason: 密码错误最大尝试次数不能大于10
```

## 环境配置

### 多环境配置

**目录结构**：

```
src/main/resources/
├── application.yml           # 默认配置
├── application-dev.yml       # 开发环境
├── application-test.yml      # 测试环境
└── application-prod.yml      # 生产环境
```

**激活方式**：

```yaml
# application.yml
spring:
  profiles:
    active: ${SPRING_PROFILES_ACTIVE:dev}
```

**不同环境的配置差异**：

| 配置项 | 开发环境 | 测试环境 | 生产环境 |
|--------|----------|----------|----------|
| JWT Secret | 默认值 | 环境变量 | 环境变量 |
| Token过期时间 | 7天 | 1天 | 7天 |
| 缓存启用 | false | true | true |
| 日志级别 | DEBUG | INFO | WARN |

**示例**：

```yaml
# application-dev.yml
order:
  platform:
    jwt:
      secret: dev-secret-key-do-not-use-in-production
    cache:
      enabled: false

# application-prod.yml
order:
  platform:
    jwt:
      secret: ${JWT_SECRET}  # 必须通过环境变量设置
    cache:
      enabled: true
```

## 最佳实践

### ✅ 推荐做法

1. **统一使用 OrderPlatformProperties**
   ```java
   ✅ @Autowired private OrderPlatformProperties properties;
   ```

2. **敏感配置使用环境变量**
   ```yaml
   ✅ secret: ${JWT_SECRET:default-value}
   ```

3. **配置项添加校验注解**
   ```java
   ✅ @Min(1) @Max(10) private int maxAttempts;
   ```

4. **配置项添加默认值**
   ```java
   ✅ private int maxAttempts = 5;
   ```

5. **配置项添加详细注释**
   ```yaml
   ✅ # 密码错误最大尝试次数（默认：5次，范围：1-10）
      max-attempts: 5
   ```

### ❌ 不推荐做法

1. **不要在代码中硬编码**
   ```java
   ❌ private static final int MAX_ATTEMPTS = 5;
   ```

2. **不要使用 @Value（除非必要）**
   ```java
   ❌ @Value("${max-attempts}") private int maxAttempts;
   ```

3. **不要在配置文件中使用明文敏感信息**
   ```yaml
   ❌ secret: my-secret-key  # 不要提交到代码仓库
   ```

4. **不要分散配置**
   ```java
   ❌ 在每个模块中创建自己的配置类
   ```

## 📋 功能概述

实现用户角色查询的完整服务层，提供接口定义、实体映射和数据库查询，支持混合方案中的数据库查询角色功能。

### 核心价值

- **解耦设计**：通过接口解耦 common 模块和 user 模块
- **可扩展性**：预留缓存接口，支持 Caffeine/Redis 扩展
- **标准规范**：使用 MyBatis 注解形式，SQL 与代码在同一文件

## 💻 代码实现

### 1. UserRoleProvider 接口

```java
package com.order.platform.common.provider;

import java.util.List;

/**
 * 用户角色提供者接口
 *
 * 功能说明：
 * - 定义用户角色查询的标准接口
 * - 避免反射调用，提高类型安全性
 * - 解耦 common 模块与 user 模块的依赖关系
 */
public interface UserRoleProvider {
    /**
     * 根据用户ID查询角色代码列表
     *
     * @param userId 用户ID
     * @return 角色代码列表，不存在时返回空列表
     */
    List<String> getRoleCodesByUserId(Long userId);
}
```

### 3. UserRoleMapper（注解形式 SQL）

```java
package com.order.platform.user.mapper;

import com.baomidou.mybatisplus.core.mapper.BaseMapper;
import com.order.platform.user.entity.UserRole;
import org.apache.ibatis.annotations.Mapper;
import org.apache.ibatis.annotations.Select;
import java.util.List;

@Mapper
public interface UserRoleMapper extends BaseMapper<UserRole> {

    /**
     * 查询用户的角色代码列表
     *
     * 查询条件：
     * - 用户ID匹配
     * - 角色已启用（is_enabled = 1）
     * - 未删除（is_deleted = 0）
     */
    @Select("SELECT role_code FROM t_user_role " +
            "WHERE user_id = #{userId} " +
            "AND is_enabled = 1 " +
            "AND is_deleted = 0")
    List<String> selectRoleCodesByUserId(Long userId);
}
```

## 🎯 使用场景

### 场景 1：AuthInterceptor 调用

```java
// AuthInterceptor.java
@Autowired
private UserRoleProvider userRoleProvider;

private List<String> getUserRoles(String token, Long userId, String uri) {
    // Token 无角色时，从数据库查询
    if (userRoleProvider != null) {
        List<String> roles = userRoleProvider.getRoleCodesByUserId(userId);
        if (roles != null && !roles.isEmpty()) {
            return roles;
        }
    }
    return Collections.singletonList("USER");
}
```

## 🔧 技术细节

### 1. 接口解耦设计

**问题**：common 模块不能依赖 user 模块（会导致循环依赖）

**解决**：定义 `UserRoleProvider` 接口在 common 模块，user 模块实现该接口

```java
// common 模块
public interface UserRoleProvider {
    List<String> getRoleCodesByUserId(Long userId);
}

// user 模块
@Service
public class UserRoleService implements UserRoleProvider {
    // ...
}
```

### 2. MyBatis 注解形式

**优点**：
- SQL 与 Java 代码在同一文件，便于维护
- 无需维护 XML 映射文件
- 适合简单 SQL 场景

**缺点**：
- 复杂 SQL 可读性较差
- 无法利用 MyBatis 的动态 SQL 强大功能

**建议**：简单查询使用注解，复杂查询使用 XML

### 3. 角色代码冗余

在 `t_user_role` 表中冗余 `role_code` 字段：

```sql
CREATE TABLE t_user_role (
    id BIGINT PRIMARY KEY,
    user_id BIGINT,
    role_id BIGINT,
    role_code VARCHAR(50),  -- 冗余字段
    is_enabled TINYINT,
    is_deleted TINYINT
);
```

**优点**：
- 避免 JOIN 查询 `t_role` 表
- 提高查询性能

**缺点**：
- 数据冗余，需要保证一致性
- 角色代码变更时需要更新关联表

## ⚠️ 注意事项

### 可选依赖处理

`UserRoleProvider` 为可选依赖（`required = false`）：

```java
public AuthInterceptor(JwtUtil jwtUtil,
                      @Autowired(required = false) UserRoleProvider userRoleProvider) {
    // ...
}
```

**原因**：
- 如果 user 模块未加载，系统仍可正常运行
- 角色获取降级为默认角色 USER
- 启动时会打印警告日志

### 空值处理

所有方法返回空列表而非 null：

```java
// ✅ 推荐
return List.of();  // 空列表

// ❌ 不推荐
return null;  // 可能导致空指针
```

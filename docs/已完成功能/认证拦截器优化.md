# 认证拦截器优化

> **功能模块**：认证授权
> **完成日期**：2026-01-07
> **相关文件**：`order-platform-common/src/main/java/com/order/platform/common/interceptor/AuthInterceptor.java`

---

## 📋 功能概述

对认证拦截器进行全面重构，解决 11 个代码质量问题，实现类型安全、内存安全、兼容性优化。

### 核心改进

- ✅ 使用接口替代反射调用
- ✅ 完善的 ThreadLocal 清理机制
- ✅ Token 前缀大小写兼容
- ✅ 支持类级别 @RequireLogin 注解
- ✅ 启动时健康检查

## 🎯 问题清单与解决方案

### 1️⃣ 反射调用缺乏类型安全

**问题**：
```java
// 之前：通过 ApplicationContext 反射调用
Object service = applicationContext.getBean("userRoleService");
List<String> roles = (List<String>) service.getClass()
    .getMethod("getRoleCodesByUserId", Long.class)
    .invoke(service, userId);
```

**解决**：
```java
// 现在：使用接口调用（类型安全）
private final UserRoleProvider userRoleProvider;
List<String> roles = userRoleProvider.getRoleCodesByUserId(userId);
```

---

### 2️⃣ ThreadLocal 清理不彻底

**问题**：仅捕获 `BusinessException`，其他异常（如 NPE）不会清理 ThreadLocal

**解决**：
```java
try {
    // 认证逻辑
    CurrentUserHolder.set(currentUser);
    return true;
} catch (Exception e) {  // 捕获所有异常
    if (userContextSet) {
        CurrentUserHolder.clear();
        userContextSet = false;
    }
    throw e;
} finally {
    // 兜底保障
    if (userContextSet) {
        log.error("【异常情况】preHandle 结束后 userContextSet 仍为 true");
        CurrentUserHolder.clear();
    }
}
```

---

### 3️⃣ Token 过期校验冗余

**问题**：先调用 `isTokenExpired()`，解析时又会捕获 `ExpiredJwtException`，重复校验

**解决**：
```java
// 之前：先校验过期，再解析
if (jwtUtil.isTokenExpired(token)) {
    throw new BusinessException(ResponseCode.TOKEN_EXPIRED);
}
Long userId = jwtUtil.getUserIdFromToken(token);

// 现在：直接解析，捕获异常
try {
    Long userId = jwtUtil.getUserIdFromToken(token);
} catch (ExpiredJwtException e) {
    throw new BusinessException(ResponseCode.TOKEN_EXPIRED);
}
```

---

### 4️⃣ 核心字段非空校验缺失

**解决**：新增 `validateUserInfo()` 方法

```java
private void validateUserInfo(TokenValidationResult result) {
    // userId 必须存在
    if (result.userId == null) {
        log.error("Token 解析后 userId 为空，可能 Token 被篡改");
        throw new BusinessException(ResponseCode.TOKEN_INVALID);
    }

    // username 可以为空（灵活性调整）
    if (result.username == null || result.username.isEmpty()) {
        log.debug("Token 解析后 username 为空（允许）: userId={}", result.userId);
    }
}
```

### 5️⃣ 注解处理不完整

**问题**：仅检查方法上的 `@RequireLogin`，不支持类级别注解

**解决**：
```java
// 检查方法或类上是否有 @RequireLogin 注解
boolean requireLogin = method.isAnnotationPresent(RequireLogin.class) ||
                     handlerMethod.getBeanType().isAnnotationPresent(RequireLogin.class);
```

**使用示例**：
```java
@RestController
@RequireLogin  // 类级别注解：所有方法都需要登录
public class OrderController {

    @GetMapping("/list")
    public Result list() {
        // 此方法需要登录（继承类级别注解）
    }

    @GetMapping("/public")
    @RequireLogin(false)  // TODO: 支持方法级别覆盖（需要扩展注解）
    public Result publicApi() {
        // 此方法不需要登录
    }
}
```

### 6️⃣ JDK 兼容性问题

**问题**：使用 `record` 类型（仅 JDK 16+ 支持）

**解决**：
```java
// 之前：record（JDK 16+）
private record TokenValidationResult(Long userId, String username) {}

// 现在：普通 class（兼容 JDK 11）
private static class TokenValidationResult {
    private final Long userId;
    private final String username;

    TokenValidationResult(Long userId, String username) {
        this.userId = userId;
        this.username = username;
    }

    public Long getUserId() { return userId; }
    public String getUsername() { return username; }
}
```

### 7️⃣ 日志空值告警缺失

**解决**：增强日志，添加 ERROR/WARN/DEBUG 级别

```java
// ERROR 级别：严重问题
if (result.userId == null) {
    log.error("Token 解析后 userId 为空，可能 Token 被篡改");
    throw new BusinessException(ResponseCode.TOKEN_INVALID);
}

// WARN 级别：业务警告
log.warn("Token 格式错误（缺少 Bearer 前缀）: {}", uri);

// DEBUG 级别：调试信息
log.debug("从 Token 获取角色: userId={}, roles={}", userId, roles);
```

### 8️⃣ Token 前缀大小写兼容

**解决**：
```java
// 统一转小写后判断前缀
String lowerAuth = authorization.toLowerCase();
if (!lowerAuth.startsWith("bearer ")) {
    throw new BusinessException(ResponseCode.UNAUTHORIZED);
}

// 使用原始字符串截取（保留 Token 大小写）
String token = authorization.substring(7).trim();
```

**支持的格式**：
- `Authorization: Bearer xxx` ✅
- `Authorization: bearer xxx` ✅
- `Authorization: BEARER xxx` ✅

### 9️⃣ UserRoleProvider 初始化校验

**解决**：启动时健康检查

```java
public AuthInterceptor(JwtUtil jwtUtil,
                      @Autowired(required = false) UserRoleProvider userRoleProvider) {
    this.userRoleProvider = userRoleProvider;

    if (this.userRoleProvider == null) {
        log.warn("┌─────────────────────────────────────────────────────────────┐");

        log.warn("│ 影响：Token 中无角色时无法从数据库查询                         │");
        log.warn("└─────────────────────────────────────────────────────────────┘");

        log.info("✅ UserRoleProvider 已注入: {}",
                this.userRoleProvider.getClass().getSimpleName());
    }
}
```

### 🔟 ThreadLocal finally 兜底

**解决**：使用标志位 + finally 块

```java
boolean userContextSet = false;

try {
    // 认证逻辑
    CurrentUserHolder.set(currentUser);
    userContextSet = true;
    return true;
} catch (Exception e) {
    if (userContextSet) {
        CurrentUserHolder.clear();
        userContextSet = false;
    }
    throw e;
} finally {
    // 兜底保障：理论上不会执行，但确保不会遗漏清理
    if (userContextSet) {
        log.error("【异常情况】preHandle 结束后 userContextSet 仍为 true");
        CurrentUserHolder.clear();
    }
}
```

## 🏗️ 工作流程

```
┌─────────────────────────────────────────────────────────────┐
│                     请求到达                                 │
└──────────────────────────┬──────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  1. 检查是否为 HandlerMethod                                  │
│     不是 → 直接放行                                           │
└──────────────────────────┬──────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  2. 检查 @RequireLogin 注解（方法或类级别）                    │
│     无注解 → 直接放行                                         │
└──────────────────────────┬──────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  3. 提取 Token（支持 bearer/Bearer/BEARER）                   │
└──────────────────────────┬──────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  4. 验证并解析 Token                                         │
│     - ExpiredJwtException → TOKEN_EXPIRED                    │
│     - SignatureException → TOKEN_INVALID                     │
└──────────────────────────┬──────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  5. 校验用户信息                                             │
│     - userId 必须存在                                        │
│     - username 可以为空                                       │
└──────────────────────────┬──────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  6. 获取用户角色（混合方案）                                   │
│     - Token 快照 → 数据库查询 → 默认角色 USER                 │
└──────────────────────────┬──────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  7. 构建并存入 ThreadLocal                                   │
│     CurrentUserHolder.set(currentUser)                       │
└──────────────────────────┬──────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  8. 请求处理完成后清理 ThreadLocal                            │
│     afterCompletion() → CurrentUserHolder.clear()            │
└─────────────────────────────────────────────────────────────┘
```

## ⚠️ 注意事项

### 启动警告处理

如果看到以下警告，说明 user 模块未加载：

```
⚠️  UserRoleProvider 未注入
影响：Token 中无角色时无法从数据库查询
```

**处理方式**：
1. 确保 `order-platform-user` 模块已添加到依赖
2. 检查 `UserRoleService` 是否正常启动
3. 或在生成 Token 时包含角色信息

### ThreadLocal 清理

**三层保障机制**：
1. 正常返回 → `afterCompletion()` 清理
2. 异常抛出 → `catch` 块清理
3. 防御兜底 → `finally` 块检测

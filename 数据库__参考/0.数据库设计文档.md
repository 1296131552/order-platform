## 一、概述

### 1.1 项目简介

订单可视化数字化管理平台是一个面向订单全生命周期管理的业务系统，涵盖订单创建、发运计划、快递跟踪、签收管理等核心业务环节，支持多角色协作、状态流转管理、异常处理、附件管理等企业级功能。

### 1.2 数据库概述

本数据库设计采用关系型数据库设计理念，支持以下核心功能：

- **订单管理**：订单创建、订单行管理、订单状态流转
- **发运管理**：发运计划制定、快递单管理、物流跟踪
- **签收管理**：签收明细记录、差异管理
- **合作方管理**：客户、供应商、承运商信息管理
- **异常管理**：异常记录、异常处理流程
- **附件管理**：凭证照片、资质文件管理
- **用户权限**：用户、角色、权限管理
- **状态管理**：统一的状态字典和状态流转规则
- **系统支撑**：操作日志、数据字典、系统配置

## 二、设计原则

### 2.1 基本原则

1. **规范统一**：统一命名、统一类型、统一约束
2. **性能优先**：合理设计索引，避免全表扫描
3. **数据安全**：敏感信息加密，权限最小化
4. **可扩展性**：支持分表分库，预留扩展字段
5. **可维护性**：表结构清晰，注释完整
6. **可读性**：命名清晰，见名知意

### 2.2 设计理念

#### 2.2.1 状态机管理

- 统一的状态字典表（`t_status_dict`）管理所有业务状态
- 业务表通过 `status_dict_id` 关联状态字典，保证状态定义统一
- 状态代码和状态名称作为冗余字段便于查询
- 状态流转规则表（`t_status_transition_rule`）定义合法状态流转

#### 2.2.2 多态关联设计

使用 `business_type` + `business_id` 双字段实现多态关联：

- **附件表**（`t_attachment`）：可关联订单、发运计划、供应商、承运商等
- **异常记录表**（`t_exception`）：可关联订单、订单行、发运计划、快递单、签收明细
- **操作日志表**（`t_operation_log`）：可关联任意业务实体

#### 2.2.3 N:M 关联设计

通过中间表实现多对多关联：

- **用户-角色**：`t_user_role` 中间表
- **角色-权限**：`t_role_permission` 中间表
- **附件-标签**：`attachment_tag_relation` 中间表

#### 2.2.4 NOT NULL 优先原则

- 尽可能使用 `NOT NULL` 和合适的默认值，避免使用 NULL
- 必须为使用默认值的字段添加注释，说明为什么使用该默认值
- 特殊情况允许使用 NULL，但必须添加注释说明原因

#### 2.2.5 软删除设计

- 统一使用 `is_deleted` 字段（TINYINT，0-未删除，1-已删除）实现软删除
- 所有查询必须过滤 `is_deleted = 0`
- 可选的 `deleted_at` 字段记录删除时间

## 四、核心业务链路

### 4.1 业务流程图

```
客户(Customer)
    │
    │ 1:N
    ▼
订单(Order) ──────────┐
    │                 │
    │ 1:N             │
    ▼                 │
订单行(OrderLine)     │
    │                 │
    │ N:1             │
    ▼                 │
供应商(Supplier)      │
                      │
    ┌─────────────────┘
    │ 1:N
    ▼
发运计划(Shipment)
    │
    │ 1:N
    ▼
快递单(ShipmentLine) ────┐
    │                    │
    │ N:1                │ 1:1
    ▼                    ▼
承运商(Carrier)     签收明细(ReceiptDetail)
```

### 4.2 核心业务说明

1. **订单创建**：客户下单，创建订单和订单行，关联供应商
2. **发运计划**：运营人员制定发运计划，关联订单和订单行
3. **快递单生成**：基于发运计划生成快递单，关联承运商
4. **物流跟踪**：记录快递单状态变更
5. **签收确认**：记录签收明细，包含差异信息

## 五、数据库表结构

### 5.1 业务表

#### 5.1.1 订单表（t_order）

**表说明**：销售订单主表，包含订单基本信息、状态、客户关联等核心数据

**主要字段**：
- `id`：订单ID（主键）
- `order_no`：订单号（唯一）
- `customer_id`：客户ID（外键）
- `status_dict_id`：状态字典ID（外键）
- `status_code`：订单状态代码（冗余字段）
- `total_amount`：订单总金额
- `order_date`：订单日期

**索引设计**：
- `uk_order_order_no`：订单号唯一索引
- `idx_order_customer_status`：客户+状态联合索引
- `idx_order_order_date_status`：订单日期+状态联合索引

#### 5.1.2 订单行表（t_order_line）

**表说明**：订单明细表，包含订单行的产品信息、数量、金额、供应商关联、收货地址等

**主要字段**：
- `id`：订单行ID（主键）
- `order_id`：订单ID（外键）
- `line_no`：行号
- `supplier_id`：供应商ID（外键）
- `product_code`：产品编码
- `quantity`：数量
- `unit_price`：单价
- `total_amount`：金额
- `status_dict_id`：状态字典ID（外键）

**索引设计**：
- `uk_order_line_order_line_no`：订单ID+行号唯一约束
- `idx_order_line_order_status`：订单ID+状态联合索引

#### 5.1.3 客户表（t_customer）

**表说明**：客户信息表，记录客户基本信息、联系方式、地址等

**主要字段**：
- `id`：客户ID（主键）
- `customer_code`：客户编码（唯一）
- `customer_name`：客户名称
- `contact_name`：联系人姓名
- `contact_phone`：联系人电话
- `address_province`：省份
- `address_city`：城市
- `address_district`：区县
- `address_detail`：详细地址

#### 5.1.4 供应商表（t_supplier）

**表说明**：供应商信息表，记录供应商基本信息、联系方式、地址等

**主要字段**：
- `id`：供应商ID（主键）
- `supplier_code`：供应商编码（唯一）
- `supplier_name`：供应商名称
- `contact_name`：联系人姓名
- `contact_phone`：联系人电话
- `address_province`：省份
- `address_city`：城市

#### 5.1.5 承运商表（t_carrier）

**表说明**：承运商信息表，记录承运商基本信息、联系方式、地址等

**主要字段**：
- `id`：承运商ID（主键）
- `carrier_code`：承运商编码（唯一）
- `carrier_name`：承运商名称
- `contact_name`：联系人姓名
- `contact_phone`：联系人电话

#### 5.1.6 发运计划表（t_shipment）

**表说明**：发运计划主表，运营人员设计的发运计划，审核通过后便可以发货

**主要字段**：
- `id`：发运计划ID（主键）
- `shipment_no`：发运计划号（唯一）
- `order_id`：订单ID（外键）
- `status_dict_id`：状态字典ID（外键）
- `status_code`：发运计划状态代码

#### 5.1.7 快递单表（t_shipment_line）

**表说明**：快递单表，包含承运商、收货方、物流单号等具体信息

**主要字段**：

- `shipment_id`：发运计划ID（外键）
- `order_line_id`：订单行ID（外键）
- `carrier_id`：承运商ID（外键）
- `tracking_no`：物流单号
- `pickup_address`：取货地址
- `delivery_address`：收货地址
- `status_dict_id`：状态字典ID（外键）

#### 5.1.8 签收明细表（t_receipt_detail）

**表说明**：签收明细表，记录具体签收数量，直接关联快递单，包含差异信息

**主要字段**：
- `id`：签收明细ID（主键）
- `shipment_line_id`：快递单ID（外键，唯一）
- `received_quantity`：签收数量
- `expected_quantity`：期望数量
- `difference_quantity`：差异数量
- `receipt_date`：签收日期

#### 5.1.9 附件表（t_attachment）

**表说明**：附件表，凭证与照片，通过多态关联支持关联多个业务实体

**主要字段**：
- `id`：附件ID（主键）
- `business_type`：业务类型（多态关联）
- `business_id`：业务ID（多态关联）
- `file_name`：文件名
- `file_path`：文件路径
- `file_size`：文件大小
- `file_type`：文件类型

```

```

### 6.2 状态管理关系

```
StatusDict (1) ──< (N) Order

StatusDict (1) ──< (N) Shipment
StatusDict (1) ──< (N) ShipmentLine
```

## 七、索引设计说明

### 7.1 索引设计原则

1. **唯一索引**：用于保证唯一性约束（订单号、用户名等）
2. **联合索引**：用于多条件查询，遵循最左前缀原则
3. **覆盖索引**：包含查询所需的所有字段，避免回表
4. **软删除过滤**：联合索引中包含 `is_deleted` 字段
5. **避免过度索引**：只保留核心查询场景的索引

### 7.2 主要索引列表

#### 7.2.1 唯一索引

| 表名 | 索引名 | 字段 | 说明 |
|------|--------|------|------|
| t_order | uk_order_order_no | order_no | 订单号唯一 |
| t_user | uk_user_username | username, is_deleted | 用户名唯一 |
| t_customer | uk_customer_code | customer_code | 客户编码唯一 |
| t_status_dict | uk_status_code_business_type | status_code, business_type, is_deleted | 状态代码+业务类型唯一 |

#### 7.2.2 联合索引

| 表名 | 索引名 | 字段 | 说明 |
|------|--------|------|------|
| t_order | idx_order_customer_status | customer_id, status_code, is_deleted | 客户状态查询 |
| t_order | idx_order_order_date_status | order_date, status_code, is_deleted | 订单日期状态查询 |
| t_order_line | idx_order_line_order_status | order_id, status_code, is_deleted | 订单行查询 |
| t_user | idx_user_enabled_locked | is_enabled, is_locked, is_deleted | 用户状态查询 |

### 7.3 索引使用建议

1. **查询优化**：优先使用索引字段进行查询
2. **排序优化**：索引字段可用于排序，避免文件排序
3. **覆盖查询**：尽量使用覆盖索引，减少回表操作
4. **索引监控**：定期监控索引使用情况，删除未使用的索引

## 九、命名规范

详细的命名规范请参考 [数据库命名规范文档](./1.数据库命名规范.md)

### 9.1 表命名规范

- **前缀**：统一使用 `t_` 前缀
- **命名方式**：使用下划线分隔（snake_case）
- **命名风格**：全小写字母
- **示例**：`t_order`、`t_order_line`、`t_user_role`

### 9.2 字段命名规范

- **命名方式**：使用下划线分隔（snake_case）
- **命名风格**：全小写字母
- **主键**：统一使用 `id`
- **外键**：使用 `表名_id` 格式，如 `order_id`、`user_id`
- **时间字段**：`created_at`、`updated_at`、`deleted_at`
- **状态字段**：`status`、`is_deleted`、`is_enabled`

### 9.3 索引命名规范

- **唯一索引**：`uk_表名_字段名`
- **普通索引**：`idx_表名_字段名`
- **联合索引**：`idx_表名_字段1_字段2`
- **示例**：`uk_order_order_no`、`idx_order_customer_status`

### 9.4 约束命名规范

- **外键约束**：`fk_表名_关联表名`
- **检查约束**：`ck_表名_字段名`
- **示例**：`fk_order_customer`、`ck_user_phone`
